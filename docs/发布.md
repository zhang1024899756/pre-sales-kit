# 发布到 PyPI

包名 `pre-sales-kit`（npm 上的同名包是另一个东西，与本项目无关）。

发布走 **Trusted Publishing（OIDC）**，本地和仓库里都不存在 PyPI API Token。
发布动作由 GitHub Actions 持一个仅本次 job 有效的短期凭据完成。

---

## 一次性配置（只做一次，约 2 分钟）

前提：已登录 [pypi.org](https://pypi.org)。没有账号先注册并**验证邮箱**（未验证邮箱无法发布）。

1. 打开 <https://pypi.org/manage/account/publishing/>
2. 滚到 **「Add a new pending publisher」**，选 **GitHub**
3. 按下表填，一个字符都不能错：

| 字段 | 值 |
|---|---|
| PyPI Project Name | `pre-sales-kit` |
| Owner | `zhang1024899756` |
| Repository name | `pre-sales-kit` |
| Workflow name | `publish.yml` |
| Environment name | `pypi` |

4. 点 **Add**

几处容易填错的地方：

- **Workflow name 要带扩展名**：`publish.yml`，不是 `publish` 也不是 `.github/workflows/publish.yml`
- **Environment name 必须和 [publish.yml](../.github/workflows/publish.yml) 里的 `environment: name` 一致**（这里就是 `pypi`）。两者不一致时 PyPI 会拒绝，错误信息只说 "not allowed to publish"，不告诉你哪个字段错了
- 这是 **pending** publisher：项目在 PyPI 上还不存在时用它；项目已经存在后，同样的东西要到 **项目页 → Publishing** 里加

配完之后不需要在任何地方保存密钥。**没有 token 可以泄露**。

## 日常发版（每次三分钟）

### 1. 本地预检

版本号在 [pyproject.toml](../pyproject.toml) 的 `version`，CHANGELOG 里也要有一节对应的。

```bash
# 单元测试与静态检查
.venv/Scripts/python -m pytest -q
.venv/Scripts/ruff check src tests
.venv/Scripts/mypy src

# 构建 + 校验（twine check 会验证 README 渲染和元数据是否合法）
rm -rf dist && uv build
uvx --from twine twine check dist/*

# 真装一遍：这一步能抓住「本地 editable 装得上、wheel 里少了文件」的问题
rm -rf .publish-venv
uv venv --python 3.11 .publish-venv
uv pip install --python .publish-venv/Scripts/python.exe dist/pre_sales_kit-*.whl
.publish-venv/Scripts/kit --version
.publish-venv/Scripts/kit selfcheck
```

`kit selfcheck` 里「安装记录」和代码版本对不上，说明装的不是刚构建的 wheel。

### 2. 提交并打 tag

标签格式 `v<版本号>`，与 `pyproject.toml` 的 `version` 必须完全一致（`v0.2.0` 对应 `0.2.0`）。

```bash
git add -A
git commit -m "chore(release): v0.2.0"
git push origin master

git tag v0.2.0
git push origin v0.2.0     # ← 这一步触发发布
```

### 3. 看结果

```bash
gh run list --workflow=publish.yml --limit 3
gh run watch <run-id>
```

成功后 <https://pypi.org/project/pre-sales-kit/> 一般 1–2 分钟内可访问，
CDN 生效可能再等几分钟（`pip install` 立即可用，网页稍慢）。

## 排错

| 现象 | 原因 | 处理 |
|---|---|---|
| `Trusted publishing identity ... is not allowed to publish` | PyPI 侧五个字段和 workflow 对不上 | 逐字核对 **Owner / Repository / Workflow name / Environment**，注意大小写和环境名 |
| `invalid-publisher` / `OIDC token ... not found` | workflow 缺 `id-token: write` | 已在 [publish.yml](../.github/workflows/publish.yml) 里写好；手动改过就别删 |
| `File already exists` | 这个版本号已经发过 | **PyPI 不允许覆盖已发布版本**。改版本号重发，不能重传同一版本（实在要撤回用 `yank`，但版本号仍被占用） |
| `twine check` 报 README 渲染失败 | README 里有 PyPI 不支持的写法 | 本地先 `twine check`，别等 CI 报 |
| workflow 根本没触发 | tag 不是 `v` 开头，或没 push tag | `git push origin v0.2.0`；`on.push.tags` 只认 `v*` |
| `kit: command not found`（装完） | Scripts 目录不在 PATH | 用 `pipx install pre-sales-kit`，或 `python -m pre_sales_kit` |

## 备选：API Token 方式（CI 不可用时）

只在无法使用 GitHub Actions 的场合用（例如内网机器、或想跳过 CI 直接发）。
代价是 token 必须存在于某个地方，用完应立刻撤销。

1. <https://pypi.org/manage/account/token/> → **Add API token**
   - 首次发布 Scope 只能选 **「Entire account」**（项目还不存在，选不了单项目）；发布成功后改成只限 `pre-sales-kit` 的 token
2. 本地上传：

```bash
# token 不要写进命令行历史，用环境变量提示输入
uvx --from twine twine upload dist/* -u __token__
# 提示 Password 时粘贴 pypi- 开头的 token，输入不回显
```

3. 传完去 PyPI 撤销这个 token

> 用 `--repository testpypi` 可以先发到测试服演练一遍（需在 <https://test.pypi.org> 另外注册账号并单独建 token）。

## 版本号约定

语义化版本：修 bug 升 patch、加功能升 minor、破坏性改升 major。

`0.x` 阶段 minor 位可以带破坏性变更（`0.2.0` → `0.3.0`），但要在 CHANGELOG 里写清。
