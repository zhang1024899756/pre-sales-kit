# 售前现场工作流

> 这份文档写的不是工具怎么用，而是**这三个工具在现场的什么时刻、解决什么问题**。
> 如果你只觉得它们是一堆命令行，那它们就只是一堆命令行。

---

## 一、工具在一天里的位置

```text
出差前一晚                     到现场（演示前 10 分钟）          演示中                   客户提问
─────────                     ──────────────────────          ──────                   ────────
kit doctor  全景体检    →     投影接上后再跑一次 doctor     →    kit seed 的数据在跑   →   kit compat 一条命令
kit seed    重置演示数据       网络 / 分辨率 / 浏览器             必要时注入异常配合告警      给出投标口径
kit compat  更新矩阵（可选）
```

关键认知：**演示环境的可靠性是一条链子，最弱的一环决定结果**。
笔记本、投影、客户网络、服务进程、演示数据、浏览器——任何一环断了，前面准备得再漂亮都白搭。
doctor 存在的意义，就是把这条链子一次性过一遍。

---

## 二、出差前一晚：20:30 的 30 分钟

**为什么是前一晚**：现场出问题，你还有一晚上可以补救；现场才发现，你只有客户等你那十分钟。

### 1. 跑一遍全景体检

```bash
kit doctor examples/doctor.yaml --html out/doctor-report.html
```

看三件事，按顺序：

1. **红项（失败）**：必须清零。这时候还没出发，任何红项都还来得及修。
2. **黄项（警告）**：逐条读提示。有些是环境事实（比如控制台编码），知道就行；有些是陷阱。
3. **数据那一行**：「最新 3 分钟前」和「最新 2 天前」是两个世界。

### 2. 能修的直接修，修完必须复检

```bash
kit doctor examples/doctor.yaml --fix          # 安全项
kit doctor examples/doctor.yaml --fix --yes    # 加上会重写数据的动作
```

工具会区分风险等级：拉起服务是低风险，重置演示数据库是高风险。
高风险动作默认不执行——**不是怕工具出错，是怕你在困的时候手滑**。

### 3. 重置演示数据，并给它一个「真实」的时间

客户第一眼看的不是你的架构图，是屏幕上的时间戳。

```bash
kit seed -m examples/points.yaml -o examples/data/demo.db
```

去看一眼预览页（`--html preview.html`）：曲线是不是有噪声、有节拍、有一个像样的量程。
如果一条线是笔直的，那不是「稳定」，是「假的」。

### 4. 打包清单（写在便签上）

- [ ] 演示数据库（`demo.db`）已生成，时间戳是今天
- [ ] 服务启动脚本能一条命令拉起来（doctor 的 `fix.command` 就是它）
- [ ] 报告 PDF / HTML 存在本地（客户现场可能没网，别指望在线打开）
- [ ] 离线安装包（浏览器、驱动、证书）
- [ ] 客户上次提的兼容性问题，`kit compat` 已经能一句话答出来

## 三、到现场：演示前 10 分钟

顺序很重要，别一进门就投屏。

### 第 1 分钟：先接投影，再看分辨率

投影仪 90% 是 1024×768，而你的演示界面是给 1920 宽设计的。
接上投影立刻跑一次 `kit doctor`，`display` 那一行会告诉你当前分辨率。
低于阈值会变黄——这不是危言耸听，是很多「排版错乱」的真实原因。

### 第 2-5 分钟：网络与端口

客户现场最常见的两种翻车：

1. **内网到不了**：数据库在客户内网，VPN 没连或网段不对。
2. **端口冲突**：客户机器上已经有别的东西占着 8080。

```bash
kit doctor examples/doctor.yaml --only 网络 --only 演示
```

不通就不要硬等：**切到本机演示环境**（数据是 `kit seed` 生成的，不依赖客户内网），
并当场说明「这一版用的是本地演示库，接入你们环境是上线阶段的事」——客户接受度远高于你猜。

### 第 6-10 分钟：完整跑一次，包含出错的那次

不要只跑「能通过的路径」。把修复动作也试一次：

```bash
# 故意停掉服务，再让工具拉起来——现场真出问题时你才不会慌
kit doctor examples/doctor.yaml --fix
```

## 四、演示中：数据与异常

### 客户问「这数据是真的吗」

诚实是唯一解，但要说对话术：

> 「这是**模拟数据**，不是你们现场的实测值。它按真实设备的物理特性生成——
> 温度以时间常数追随负载、电流有启动冲击、功率因数有界波动。
> 演示的是我们的**分析与告警能力**，数据接进来之后行为是一样的。」

这句话的可信度，来自屏幕上的曲线确实像真的：有噪声、有节拍、有上下界。

### 需要一个告警来演示

不要手动改数值——那会留下明显的「一条竖线」。用异常注入：

```bash
kit seed -m points.yaml -o demo.db --inject-fault 14:20-14:35   --fault-point 主轴电流 --fault-kind ramp --fault-magnitude 0.23
```

注入的异常在物理上仍然成立（缓升而不是瞬跳），告警系统看到的是「真的一个异常趋势」，
而不是「一个被改过的数」。

## 五、客户问兼容性：30 秒应答

### 三步

1. **查**：`kit compat check --os ... --db ...`
2. **看前提**：结论是「部分支持」时，说明里一定写了前提（补丁、配置、版本）
3. **给口径**：
   - 完全支持 → 「支持」
   - 部分支持 → 「支持，但需要满足 XXX 前提」，并把前提写进偏离表
   - 不支持 → 「不支持」，**同时给替代方案**（升级版本 / 换组合），不要只说不行
   - 未收录 → 「这个组合我们还没验证过，我确认后回复你」，绝不当场拍「支持」

### 三种不要答「支持」的情况

| 情况 | 为什么 |
| --- | --- |
| 维度没收录（返回 `unknown`） | 没验证过的组合，答「支持」是给交付挖坑 |
| 单维度支持、但组合是 `unsupported` | 组合冲突真实存在（补丁依赖打架） |
| 依赖已 EOL 的组件（MySQL 5.7 / Oracle 11g） | 支持是「技术上能跑」，不是「建议这么干」 |

### 把结论变成方案书里的一张表

```bash
kit compat matrix --html out/compat.html --brand "公司名"
kit compat matrix --md out/compat.md
```

表格的措辞是「部分支持 / 不支持」，不是「支持情况见文档」——**模糊的表述在评审时会被追问**。

## 六、常见翻车与对应动作

| 现象 | 真实原因 | 动作 |
| --- | --- | --- |
| 服务起不来，端口「连接超时」 | 服务没启动 / 防火墙拦 | `kit doctor --fix` 拉起；仍失败看 fix 的命令输出 |
| 页面能开，但数据是前几天 | 演示库没重置 / 时区错 | `kit seed` 重生成；`env` 检查时区 |
| 中文显示成问号 | 控制台编码 GBK | 报告本来就是 UTF-8 HTML；终端临时 `chcp 65001` |
| 投影上排版错乱 | 分辨率 1024×768 | `display` 检查；演示页别写死更宽的布局 |
| 客户问的组件不在矩阵里 | 矩阵没维护 | 当场答「确认后回复」，回去补 `matrix.yaml` |
| 证书过期，HTTPS 打不开 | 演示证书没人管 | `env` 的 `cert_path` 检查，阈值 14 天 |

## 七、这套工具没解决的部分

诚实地列出来，比假装全能更有用：

- **招标条款逐条应答**：涉密、格式各异，不适合工具化。
- **方案架构图**：画图是思考过程，工具替代不了。
- **客户点位表归一化**：Excel 格式千奇百怪，值得做但工作量大（v2 再说）。
- **真实设备接入**：那是产品的事，不是工具箱的事。

工具的边界越清楚，别人越信它能做好的那部分。

## 八、附录：一页清单

```text
【T-1 晚上】
□ kit doctor --html        → 红项归零
□ kit doctor --fix --yes   → 修完复检全绿
□ kit seed --html          → 数据时间戳是今天、曲线不是直线
□ 离线包 / 报告 / 许可证已打包

【T-0 现场】
□ 接投影 → kit doctor --only 显示
□ 网络 → kit doctor --only 网络
□ 完整跑一次（含一次故意失败再修复）
□ 报告本地打开确认（断网）

【演示中】
□ 客户问数据真假 → 说「模拟数据 + 物理模型」
□ 需要告警 → 用 --inject-fault，不手改数值

【客户提问】
□ kit compat check → 按「支持 / 部分支持 + 前提 / 不支持 + 替代 / 未收录」四种口径回答
□ 未收录的，承诺回复时间，不当场拍板
```
